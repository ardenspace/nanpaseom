# Plan: 난파섬 세이브 연속성 정리 — 코드-열쇠 가장자리 묶음

## Phase 1: 지난 런이 남긴 위생 2건

배포 env에 오타를 넣어도 Secure 쿠키가 꺼지지 않고, 안전 이벤트가 조용히
증발하던 경로가 시끄럽게 죽는다 — 사람이 env 값을 바꿔가며 확인 가능.

Contracts: B6, B7

- [x] 계약 pin: B6 허용목록 판정(`"1"`/`"true"`만 켜짐, 오타·`"yes"`·
      `"on"`·빈값은 꺼짐)과 B7 예외 실패(+ 기존 호출부 전제 만족)를
      실패 테스트로 먼저 작성. 기존 falsy 6종 pin 테스트를 허용목록
      의미로 갱신하는 것도 이 단계.
- [x] `session_cookie.py` 판정 반전 구현 — falsy 목록 방식 폐지,
      허용목록만 Secure 생략.
- [x] `strike.register` 전제 위반을 실제 예외로 — bare `assert` 금지
      (`python -O` 에서 조용한 무동작으로 되돌아가므로).

## Phase 2: 코드 회전과 추측 방어

플레이어가 위험해진 세이브 코드를 죽이고 새 코드를 받을 수 있고, 코드를
무작위로 두들기는 시도는 429로 막힌다.

Contracts: B1, B2, B3

조기 당김 주의: B1은 서버 계약 + 프론트 어포던스를 함께 포함하므로 이
페이즈에서 프론트를 건드린다. Conventions 4에 따라 훅 추출이 UI 작업에
선행하고, 프론트 계약을 테스트로 pin 하려면 vitest가 먼저 있어야 한다 —
그래서 vitest 도입이 이 페이즈의 첫 단계다(Req 9의 절반이 여기서 소모됨).

- [x] vitest 도입 — 설정(DOM 환경·렌더 라이브러리 선택), 실행 스크립트,
      기존 순수 로직 1건 최소 pin으로 러너가 실제로 도는 것을 확증.
- [x] 계약 pin: B1(rotate 서버 계약 + 회전 도달 가능성) / B2(발급
      idempotency 회귀 — 회전 도입이 깨뜨리지 않음) / B3(모든 시도 집계,
      성공도 리셋 안 함, 초과 시 429)를 실패 테스트로 작성.
- [x] `POST /save-code/rotate` 구현 — 401/banned/ok 분기, 미발급 세션은
      첫 민팅으로 성공, 문구는 rules YAML.
- [x] redeem 시도 제한 구현 — 직결 IP 기준(XFF 불신뢰), 수치·문구는
      rules YAML, 윈도우 만료 기록 정리, 테스트에서 결정적 초기화 가능.
- [ ] `App.tsx` applyTurn+sendTurn 훅 추출(동작 보존) + `/turn` 401 자동
      복구 경로 회귀 pin — B5 재노출 조건이 이 경로와 맞물리므로 여기서
      고정한다.
- [ ] 회전 UI — 세이브 코드 보기 경로에서 도달, "이전 코드는 더 이상 쓸
      수 없다" 명시, 모순되는 기존 문구("다시 확인해도 코드는 바뀌지
      않습니다") 개정.

## Phase 3: 갈아타기 탈출구

코드로 갈아타기 직전에, 지금 하던 진행의 코드를 그 자리에서 받아둘 수
있다 — 경고만 보고 버리는 상황이 사라진다.

Contracts: B4

조기 당김 주의: B4의 "무조건 확인 유지"와 "타이틀 상시 이어하기 입구"는
이미 배포된 동작이다. 이 페이즈의 pin은 신규 구현이 아니라 회귀 고정
(적합성 확인)이고, 신규 작업은 탈출구뿐이다.

- [ ] 계약 pin: B4 — 무조건 확인(진행 유무로 건너뛰지 않음) 회귀, 상시
      입구 회귀, 탈출구 존재와 실패 분기(401/밴/서버 오류/네트워크에서
      솔직한 문구 + redeem 계속 가능)를 실패 테스트로 작성.
- [ ] 탈출구 구현 — 다이얼로그 안에서 현재 세션 코드 발급·표시·복사,
      실패해도 갈아타기를 막지 않음, 문구는 톤 홈.

## Phase 4: 코드 뽑기 넛지

코드를 한 번도 안 받은 플레이어가 진행이 쌓인 시점에 한 번 권유를
받는다 — 쿠키가 사라져도 돌아올 열쇠를 쥐고 있게 된다.

Contracts: B2b, B5

- [ ] 계약 pin: B2b(진입 응답 `has_save_code` — bootstrap과 redeem 양쪽,
      기존 필드 불변) + B5(코드 보유 세션엔 절대 미노출, 임계값 경계 양쪽,
      닫으면 재노출 없음, 코드 없는 새 세션 진입 시 재노출)를 실패
      테스트로 작성.
- [ ] `has_save_code` 서버 구현 — 세션 진입 wire shape 공유 지점에 가산.
- [ ] 넛지 프론트 구현 — 판정은 순수 함수(누적 턴 수), 임계값·문구는
      프론트 톤 홈, dismiss 저장과 새 세션 재노출 규칙, 발급/회전 성공 시
      즉시 참으로 갱신.

## Phase 5: 기록과 확증

결정 이유가 ADR로 남고, 전 게이트가 그린이며, 새로 빌드한 산출물로
스모크가 확인돼 공개 배포 판단이 가능해진다.

Contracts:

- [ ] ADR — 세이브 코드 회전(세션당 활성 코드 1개, 무유예, 소각 없음,
      침입자 축출 아님).
- [ ] ADR — redeem 시도 제한(직결 IP·XFF 불신뢰·단일 프로세스 메모리,
      배포 런 재검토 필수).
- [ ] ADR — `has_save_code` 와 넛지 best-effort(코드 보유 ≠ 실제 기록).
- [ ] `docs/mechanic-spec.md` 정렬(+ mapping-spec 해당 행 확인) — 상세는
      ADR 위임, 권한 문서 중복 금지.
- [ ] 전 게이트 재실행(pytest / check_yaml / 하드코딩 grep / `bun run
      build` / vitest) + dist 재빌드 후 스모크 수행, 결과를
      `.talpi/manual-check.md` 에 기록.
