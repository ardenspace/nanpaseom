## Problem Statement

Sub-1 이 `build_prompt(npc_name, awareness, memory_tags, hooks_runtime) -> str` 를 결정성 있는 pure function 으로 고정했다. 그 string 은 LLM API 의 `system` 필드 한 장이다 (Sub-1 Decision 4). 그러나 그 string 은 *아직 어떤 모델에도 닿지 않았다*. `messages` orchestration, 실제 LLM 호출, JSON reply 파싱, awareness 서버 클램프, Postgres 영속화 — 이 전부가 Sub-1 이 명시적으로 Sub-2 로 넘긴 경계 바깥이다.

Sub-2 의 첫 단계 = **그 경계를 잇는 가장 얇은 vertical slice**. 수리공 한 명, `POST /turn` 하나. 목표는 단 하나의 명제를 증명하는 것:

> 턴 N 의 `awareness_delta` 가 서버에서 `[-10,+10]` 클램프되어 누적·영속화되고, 턴 N+1 의 `build_prompt` 가 그 갱신된 awareness 로 *다른 band* 를 렌더한다.

이 loop 가 닫히면 mechanic-spec 의 4 pillar (engine / context-mgmt / safety / error-handling) 가 *콘텐츠·UI 가 자라기 전에* 한 NPC 위에서 검증된다 — mechanic-spec Week 2 ordering 그대로 (line 237, 249).

이 단계가 빠지거나 production 전체 (5개 항목 + 프론트 + 안전 풀스택) 를 한 번에 시도하면, slice 의 핵심 가치 (pillar 가 틀렸으면 Week 2-3 에 틀린 걸 안다) 가 사라진다. 따라서 **얇게 자르는 것 자체가 spec-driven ordering 의 실행 형태**.

## What Makes This Cool

- **Sub-1 의 산출물이 처음으로 살아 움직인다** — offline pure string 이 실제 모델의 `system` 으로 들어가 NPC 가 awareness 메커니즘대로 깨어난다.
- **결정성의 연속** — Sub-1 의 snapshot 결정성이 Sub-2 에서 위협받는다 (LLM = 비결정). 이 spec 은 *결정성 validator* 와 *비결정 model-behavior eval* 을 분리해 gate 의 결정성을 보존한다. Sub-1 의 테스트 철학이 Sub-2 에까지 박힌다.
- **tool-use 가 spec 의 가정을 갱신한다** — mechanic-spec error-handling 은 "믿을 수 없는 local Gemma" 전제로 쓰였다. Claude tool-use 는 그 전제를 뒤집는다. 이 변경이 *silent 코드 if 가 아니라 ADR + spec 갱신* 으로 처리되는 것이 spec-driven 권한 경계의 실행.
- **slice 산출물이 Sub-2b 의 의존성** — turn loop 가 안정 안 되면 안전 풀스택·프론트 시작 안 함. fail-fast 가 sub 단위로 확장 (Sub-1 패턴 계승).

## Constraints

기존 `mechanic-spec.md`, `world-spec.md`, `mapping-spec.md` + 26 ADR + Sub-1 산출물 모두 상속. 본 spec 이 추가 부과:

- **Sub-1 동결**: `app/prompt_builder/` 의 public API (`build_prompt` signature) 변경 금지. Sub-2 는 그 위에서만 조립. (summary param 신설 유혹 = 본 spec 이 거부, Open Question 으로 이관.)
- **얇음 락**: 수리공 1명. `POST /turn` 1 엔드포인트. pytest/httpx 구동. **브라우저/React/Vite 없음.**
- **영속화 = Real Postgres**: Approach C 의 "Postgres source of truth" lock 존중. 최소 스키마 (추가만, locked 스키마 변경 X).
- **모델 = Anthropic API + tool-use**: 사용자 directive. mechanic-spec 의 model-tier 후보군 (local Gemma / Groq / gpt-4o-mini) 에 없던 선택 → ADR 대상.
- **결정성 gate**: 매 commit 테스트는 live LLM 호출 없이 결정적. live signal 은 off-gate 격리.
- **Fail-fast 계승**: Layer 1/4 위반·API 에러 → 정의된 행동. silent default X.

## 권한 경계 (이 spec 내)

- **이 spec** = Sub-2 slice 의 *디자인 의도 + 결정 lock + scope*. 구현 detail / 함수 signature 의 최종 모양 = plan 단계.
- **ADR (신규 2개)** = 이 spec 안에서 결정된 authority-touching 결정 2개의 audit trail (아래 Decisions 참조).
- **`docs/mechanic-spec.md` Error-Handling 섹션** = tool-use 계약으로 갱신될 권한 문서. 본 spec 이 변경 *의도* 를 lock, 실제 edit 은 plan 의 첫 phase.
- **`docs/mapping-spec.md`** = turn-output 메커니즘 행 re-align 대상.
- **`npcs/surigong.yaml` `diegetic_fallback`** = fallback 라인의 source of truth (이미 CLAUDE.md 필수 키). Sub-2 는 *읽음*, 하드코딩 X.

## Decisions Locked (이 brainstorming 산물)

### Decision 1 — Sub-2 첫 deliverable = 수리공 단독 thin backend vertical slice

**Context**: handoff 의 Sub-2 5개 항목은 동질하지 않다 — vertical slice (infra+wiring) 2개, test 1개, enforcement/hygiene 2개. "e2e" 는 browser→DB 와 API-contract→DB 로 모호. mechanic-spec Week 2 ordering 은 "pillar 를 1 NPC 로 먼저 증명" 을 명령.

**Decision**: 첫 deliverable = 수리공 1명, `POST /turn`, pytest/httpx 구동, 브라우저 없음. build_prompt → Claude API → JSON validate → clamp → persist → next turn. LLM 출력 회귀 테스트 + Layer 1 입력 prefilter 포함. enforcement (grep + PR 체크리스트) 는 slice 꼬리에 fold.

**Rejected**:
- Slice + 풀 safety (Layer 2 Moderation + 2-strike) — OpenAI 의존 + DB 스키마 + frame-breaking UX 가 한꺼번에 유입, slice 비대.
- 풀 5-item Sub-2 (browser e2e 포함) — Week 2 ordering 위반, 한 plan 에 독립 서브시스템 과다 → decompose 필요.

### Decision 2 — 영속화 = Real Postgres, 최소 스키마

**Context**: mechanic-spec Approach C (line 96) 가 "Postgres source of truth" + `npc_state.memory_tags` 를 Postgres `text[]` 로 lock. SQLite/in-memory 는 `text[]` 등가물이 없어 JSON 인코딩 → 영속화 코드 throwaway + locked 스키마와 contract 분기 (mild drift).

**Decision**: Docker Postgres. slice 가 쓰는 테이블만:
- `npc_state (session_uuid, npc_id, awareness int, memory_tags text[], summary text nullable, updated_at)` — PK `(session_uuid, npc_id)`.
- `chat_logs (session_uuid, npc_id, turn_index, role, content, reply_json_raw, created_at)`.

`sessions.save_code` / `global_state` / playthrough 컬럼 / safety 컬럼 (`warning_count`/`banned_at`/`safety_events`) 은 *스키마에 아예 안 넣음* (Sub-2b 에서 추가만, 변경 X). `session_uuid` 는 엔드포인트가 trivial 발급 (쿠키/Cloudflare 없음 — 첫 턴에 mint 후 반환, 테스트는 고정 uuid 주입).

**Rejected**:
- SQLite/in-memory — 위 throwaway + drift.
- Repository 추상화 + 2 backend (Protocol + InMemory + Postgres) — slice 가 아직 안 필요한 추상화 layer (YAGNI).

### Decision 3 — 턴 JSON 계약 = Anthropic tool-use (forced structured output) (→ ADR 신규)

**Context**: mechanic-spec Error-Handling (line 199-212) 전체가 *prompt-for-JSON → parse → retry once → diegetic fallback* 로 쓰임 — local Gemma 가 clean JSON 을 못 내는 전제. Claude tool-use 는 API 가 schema 를 강제 → malformed JSON 거의 불가. 또한 Claude 자체가 mechanic-spec 의 model-tier 후보군 (local Gemma / Groq / gpt-4o-mini, line 233) 에 없음.

**Decision**: turn 스키마 (`reply` / `awareness_delta` / `reason` / `memory_tags` / `choices`) 를 tool (`emit_turn`) 로 정의, 모델이 반드시 그 schema 로 응답. diegetic fallback 은 *parse 실패가 아니라 API/timeout 에러 전용* 으로 재정의. claude-api 스킬 기본값 (prompt caching 자동) 활용 — `system` 블록에 cache_control.

이 결정은 두 authority-touching 사실을 묶는다: (a) 모델 tier = Claude (후보군 deviation), (b) JSON 계약 = tool-use (error-handling 전제 대체). **하나의 ADR + mechanic-spec Error-Handling 섹션 갱신** 으로 기록.

**Rejected**:
- Prompt-for-JSON + retry (spec 그대로) — 미래 local-Gemma tier 이식성은 유지하나 fragile + Claude 강점 버림. spec 변경은 없지만 tool-use 미사용 = 의도적 약화.
- Hybrid (tool-use 지금 + parse seam 유지) — failover 추상화 lock 과 정합하나 thin slice 에 seam 조기 도입 (YAGNI). seam 은 Sub-2b 의 tier 추상화 때.

### Decision 4 — LLM 출력 회귀 테스트 = 2-tier (결정적 gate + off-gate live eval)

**Context**: ADR 0023 이 "NPC 발화 sample_lines verbatim 복사 ≤ N회/대화" 를 Sub-2 invariant 후보로 명시. 그러나 live LLM 은 비결정 — Sub-1 의 결정성 gate 철학과 충돌. "회귀 테스트" 안에 두 가지가 숨어있음: (a) 순수 *validator* (이 reply 가 sample_line 을 verbatim 복사하나? reply ≤ 300? band 별 choice count/tone 유효?) = 결정적, (b) model *behavior* eval (Claude 가 실제로 N턴 verbatim 회피하나?) = 비결정.

**Decision**: 둘을 분리.
- **Gate (매 commit, 결정적)**: 순수 validator 를 synthetic good/bad fixture 로 테스트 (sample_line 을 일부러 복사한 reply 가 잡히는지 포함). + 턴 loop 통합 테스트는 stub Anthropic client (캔드 `tool_use` 응답) 로 request→parse→clamp→persist 검증 — live key 없이 결정적. validator 는 곧 Layer 4.
- **Off-gate (`pytest -m live`, 수동/nightly)**: 실제 Claude N턴 호출, sample_lines verbatim ≤ N 통계적 assert. 유일한 real-model signal. flaky/비용 격리.

**핵심**: 모델을 결정적으로 만들 수 없다 — validator 를 떼어 gate 하고, live eval 은 정직한 off-gate signal 로 둔다. Sub-1 결정성 규율 보존.

**Rejected**:
- Live-only eval — 정직하나 flaky + 비용 + 결정성 gate 포기.
- Validator-only, live eval defer — gate 완전 결정적이나 모델 실제 경향 미측정, ADR 0023 invariant 미룸 (사용자 IN-list 위반).

### Decision 5 — Context-window 범위 = 8-turn verbatim window IN, running summary defer

**Context**: mechanic-spec context 전략 = 8-turn verbatim + 10-turn summary + memory_tags injection. memory_tags 는 이미 build_prompt 경유. 그러나 running summary 는 *system prompt 에 inject* 로 명세 (line 192) — Sub-1 build_prompt 에 summary param 없음. 포함 = Sub-1 API 동결 위반.

**Decision**: 8-turn verbatim window 만 IN (chat_logs → messages, cheap). 10-turn running summary 는 Sub-2b 로 defer (turn 10+ 에서만 trigger → loop 증명과 무관). summary-injection seam (system 합치기 vs build_prompt param vs messages) 은 Open Question 으로 명시. Sub-1 동결 유지.

**Rejected**:
- Summary 포함 (build_prompt 에 param 신설) — Sub-1 API 변경 + 16-cell snapshot/property 재생성, slice 팽창.
- 둘 다 defer (current input 만) — 단기 대화 memory 없어 spec turn loop 와 멀어짐 (대화 응집성 0).

## Architecture (the seam)

Sub-1 = `system` 한 장. Sub-2 = 그 주위 전부.

```
build_prompt(npc, awareness, memory_tags, hooks) ──→ system  ─┐  (prompt-cache: cache_control)
last-8-turns from chat_logs ──→ messages[0..n-1]              ├──→ Anthropic API (tool-use: emit_turn)
current player input (Layer 1 통과) ──→ messages[-1]          ┘            │
                                                                            ▼
                          tool_use result { reply, awareness_delta, reason, memory_tags, choices }
                                                                            │
              Layer 4 validate (reply ≤ 300, leak 차단, choice count == band, tone ∈ palette)
                                                                            │
       clamp delta [-10,+10] → new awareness [0,100], memory_tags append (vocab-filter, max 3, dedupe)
                                                                            │
              persist npc_state + chat_logs (Postgres) ──→ 턴 N+1 의 build_prompt 가 새 band 렌더
```

awakening loop 증명 = 턴 N+1 의 `build_prompt` 가 턴 N 의 클램프·영속된 delta 때문에 *다른 band* 를 렌더. Layer 1 은 API 호출 *전* 입력을 prefilter.

**Sub-1 ↔ Sub-2 경계 (재확인)**: Sub-1 = `system` string (동결). Sub-2 = `messages` orchestration + LLM 호출 + Layer 1/4 + clamp + Postgres.

## Components (파일/모듈 레이아웃)

**신규**:

```
app/
├── api/            # FastAPI: POST /turn, 첫 턴 session_uuid mint
├── llm/            # Anthropic client wrapper (emit_turn tool schema, system cache_control)
├── turn/           # the loop: build_prompt → llm → Layer4 validate → clamp → persist
├── safety/         # Layer 1 (input prefilter) + Layer 4 (output validator) — pure fns
└── store/          # Postgres repo: npc_state, chat_logs (asyncpg or psycopg)
migrations/         # SQL: 최소 스키마 (Decision 2)
tests/
├── turn/           # gate: stub-client 통합 (request→parse→clamp→persist)
├── safety/         # gate: validator synthetic good/bad fixtures
└── live/           # off-gate (-m live): real Claude, verbatim ≤ N eval
```

`app/prompt_builder/` (Sub-1) 은 import 만, **변경 없음**.

**Enforcement (slice 꼬리)**:
- pre-commit grep — `app/` 안 NPC 대사 하드코딩 금지 (sample_lines / diegetic_fallback literal 또는 한국어 대사-shape 문자열 탐지).
- `PULL_REQUEST_TEMPLATE.md` — mechanic 변경 시 mapping-spec 리뷰 강제 라인.

**의존성 신규**: `anthropic`, `fastapi`, `uvicorn`, `httpx` (test), `asyncpg` 또는 `psycopg[binary]`. 기존 상속: `pydantic>=2`, `jinja2`, `pyyaml`, `pytest`.

## Data Flow (turn loop)

**`POST /turn` 요청** (slice):
```json
{ "session_uuid": "…(없으면 첫 턴, 서버 mint)…", "npc_id": "surigong", "player_input": "…" }
```

**내부 단계**:
```
1. Layer 1 prefilter(player_input)
   • 길이 캡 (KO 200 / EN 500) 초과 또는 페르소나-공격 키워드 hit
   • → diegetic 무관심 폴백 라인 반환, LLM 호출 X, awareness 변화 X (turn 무효 처리)

2. store.load_npc_state(session_uuid, "surigong") → (awareness, memory_tags, summary)
   • 첫 턴 = 기본값 (awareness 0, memory_tags [])

3. store.load_recent_turns(session_uuid, "surigong", limit=8) → verbatim window

4. system = build_prompt("surigong", awareness, memory_tags, hooks_runtime)   # Sub-1, 동결
   messages = window + {role: "user", content: player_input}

5. llm.call(system, messages, tools=[emit_turn])  # tool-use 강제, system cache_control
   • API/timeout 에러 → diegetic fallback (surigong.yaml diegetic_fallback), turn_index 진행, awareness 불변

6. Layer 4 validate(tool_result, band)
   • reply ≤ 300, leak 키워드 차단, choices 길이 == band count, tone ∈ palette
   • 위반 → 사전 fallback 라인 세트 (surigong.yaml)

7. new_awareness = clamp(awareness + clamp(delta, -10, +10), 0, 100)
   new_tags = dedupe((memory_tags + vocab_filter(result.memory_tags))[:누적], max 3/turn)

8. store.save_npc_state(...) + store.append_chat_log(player turn, npc turn, reply_json_raw)

9. 반환: { reply, choices, session_uuid }  # awareness 정수는 노출 안 함 (mechanic-spec: 숫자 비노출)
```

**Edge case (spec-level, plan 에서 구체화)**:
- band 경계: Sub-1 `resolve_band` 규칙 그대로 (low inclusive, high exclusive, 마지막 band 100 inclusive).
- `choices` == `[]` (band 85-100): Layer 4 가 빈 배열을 *정상* 으로 통과, UI 자유 입력만 (slice 는 UI 없음 — 계약만 검증).
- session_uuid 미존재: 서버 신규 mint + npc_state 기본 row 생성.
- **hooks_runtime 의 ruby 변수**: 수리공 `build_prompt` 는 `player_total_rubies_given_to_this_npc` (int) 를 *필수* 로 요구 (없으면 renderer `ValueError`). 그러나 낚시/루비 economy 는 out-of-scope. → slice 는 이 값을 **고정 `0` 으로 주입** (플레이어가 루비를 줄 경로가 없으므로 0 이 정답). 루비 누적은 economy 가 도착하는 v1.1 에서 npc_state 컬럼화 — 그때까지 slice 의 turn loop 가 `{"player_total_rubies_given_to_this_npc": 0}` 를 build_prompt 에 넘김. (이 stub 이 "코드 내 NPC 데이터 하드코딩" 이 아님을 주의: 대사/톤이 아니라 runtime hook 값, build_prompt 계약의 필수 입력.)

**NFR**:
- Latency: API 왕복 의존 (slice 는 측정 안 함, Sub-2b spike).
- 결정성: turn loop 자체는 stub-client 로 결정적 검증 가능. live 부분만 비결정.
- prompt caching: `system` 블록은 NPC/band 별 정적·대용량 → cache_control breakpoint 이상적 (claude-api 스킬 자동).

## Error Handling

**원칙**: tool-use 가 parse-failure 경로를 거의 dead 로 만든다. fallback 표면 재정의.

| 오류 | 발생 | 행동 |
|---|---|---|
| Layer 1 키워드/길이 hit | API 호출 전 | diegetic 무관심 폴백, turn 무효, awareness 불변 |
| Anthropic API 에러/timeout | llm.call | diegetic fallback (surigong.yaml `diegetic_fallback`), turn_index 진행, awareness 불변 |
| tool 미호출 (이론상 드묾) | llm.call | API 에러와 동일 처리 |
| Layer 4 위반 (count/tone/leak/len) | validate | 사전 fallback 라인 세트 (surigong.yaml), 로그 |
| awareness ∉ [0,100] (내부 버그) | clamp | 방어적 clamp (정상 경로에선 불가) |
| Postgres 쓰기 실패 | store | propagate (slice 는 5xx — 프론트 diegetic 은 Sub-2b) |

mechanic-spec Error-Handling 3 failure mode 중 (1) JSON parse 는 tool-use 로 near-dead, (2) backend timeout 은 fallback (failover 는 Sub-2b), (3) Moderation 은 Sub-2b. 이 재정의가 **mechanic-spec 섹션 갱신 트리거** (ADR 동반).

## Testing

### Gate (매 commit, 결정적)

**Layer 1/4 validator (`tests/safety/`)** — 순수 함수, synthetic fixture:
- Layer 1: 키워드 hit / 길이 초과 입력 → 차단 반환. clean 입력 → 통과.
- Layer 4: sample_line 을 일부러 verbatim 복사한 reply → 잡힘. reply > 300 → 잡힘. 잘못된 choice count/tone → 잡힘. leak 키워드 → 잡힘. 정상 reply → 통과.

**Turn loop 통합 (`tests/turn/`)** — stub Anthropic client (캔드 `tool_use` 응답):
- request → build_prompt 호출 → stub 응답 파싱 → Layer 4 → clamp → Postgres 저장 검증.
- **핵심 회귀**: 턴 N delta +8 (band 0-30 내) → 영속 → 턴 N+1 의 system 이 갱신 awareness 반영 (band 전이 케이스 포함 assert).
- API 에러 stub → diegetic fallback (surigong.yaml) 반환, awareness 불변 assert.

Postgres 테스트: 로컬 docker pg 또는 testcontainers (plan 에서 택1).

### Off-gate live eval (`tests/live/`, `pytest -m live`)

- 실제 Claude N턴 (수리공) 호출 → 각 reply 에 validator 적용.
- **invariant (ADR 0023)**: sample_lines verbatim 복사 ≤ N회 (N = plan 에서 확정). reply ≤ 300, tone/count 유효.
- 수동/nightly. ANTHROPIC_API_KEY 필요. CI gate 아님.

### Enforcement 테스트

- grep hook: `app/` 에 NPC sample_line/diegetic_fallback literal 심으면 fail (의도적 위반 fixture 로 hook 자체 검증).
