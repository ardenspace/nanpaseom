## Problem Statement

기존 PRD (`arden-main-design-20260424-014454.md`, 705줄)는 *시스템 층위* (각성 게이지, UI 축소 3→2→1→0, 보트 모먼트 5분기 엔딩, 4-layer 안전, 세이브 코드, Postgres 스키마, 루비 경제 등)가 13개 grilling branch로 hardened되어 매우 정밀하다. 그러나 *서사 층위*가 비어있어 — *왜* NPC가 트로프에 갇혀 있는지, *왜* 플레이어는 떠나야 하는지의 동기 부여가 약하다. 결과: 이전 레포에서 코드가 중구난방으로 짜이고, 솔로 디자이너의 멘탈 모델이 흔들려 학습 효용도 떨어졌다.

이 설계 문서가 해결하는 두 가지:

1. **서사 층위 보강** — "망각의 섬" 세계관을 추가해, 기존 hardened 메커니즘에 *narrative justification*을 1:1로 매핑한다. 메커니즘 변경 없음. lore가 *왜 이 메커니즘인지*를 설명한다.
2. **Spec-driven 셋업** — 새 레포에서 처음부터 mechanic-spec / world-spec / mapping-spec 3문서 + per-NPC YAML + global rule YAML 구조로 시작한다. 시스템 프롬프트는 코드에서 하드코딩하지 않고 빌더가 YAML에서 생성한다. 솔로 디자이너의 *학습 목표* (spec-driven workflow, rule-based automation, structured context, agent execution environment design)의 vehicle.

## What Makes This Cool

- **시스템 층위 ↔ 서사 층위가 1:1 매핑**된다. 기존 PRD의 모든 메커니즘이 망각의 섬 lens 하나로 *의미 부여*를 받는다 (mapping table 참조). 메커니즘 = lore의 *작동 형태*. 둘이 분리된 layer가 아니라 같은 thing의 두 얼굴.
- **혜안 = "이름밖에 안 남은 자"**. 다른 NPC가 호칭만 남은 망각된 자라면, 혜안은 이름밖에 안 남은 *못 잊은 자*. 이전 PRD에서 "혜안만 진짜 이름"이 디자인 비대칭(bug)이었는데, 망각의 섬 lore에서 이게 *feature*가 된다. 그녀의 모든 톤 차이가 lore-justified.
- **두 종류의 깨어남.** 수리공 / 어부 / 할머니 = *기억하는 깨어남* (잊었던 것을 다시 떠올림). 혜안 = *수긍하는 깨어남* ("역시 그랬구나"). 4개 깨어남 축이 아니라 *3 + 1 메타* 구조라서 narrative ecology가 더 정교.
- **Spec이 코드를 *생성*한다.** NPC YAML → system prompt 빌더 → LLM 입력. 게임 밸런스 튜닝이 코드 수정이 아니라 YAML 수정. LLM-product 포트폴리오 시그널.

## Constraints

기존 PRD의 Constraints 모두 상속 (솔로 빌더 12-16주, 공개 URL, 한국어 우선, $0.10/playthrough LLM cost ceiling, 안전 4-layers + 2-strike, 모바일 launch-gating, CC0 픽셀 아트, Mac Mini Tier 1 with Groq/OpenAI 페일오버). 본 문서는 *세계관 + spec 구조*만 다루며, 메커니즘 / 안전 / 인프라 / 일정은 mechanic-spec에서 권한을 가진다.

추가 constraint (이 문서가 부과):

- **메커니즘 변경 없음.** 망각의 섬 lore는 *해석 레이어*. 보트 게이트, awareness band UI, memory_tags vocab, 4-layer 안전 등은 PRD에서 변경되지 않는다.
- **혜안 4-band escalation의 85+ 라인만 교체** (lore-driven 개선). 0-30 / 30-60 / 60-85 라인은 유지, 톤 라벨만 명시.
- **사이비 archetype은 v1.1.** 4-NPC 슬롯에 들어가지 않음. ADR 0017로 deferral 명시.

## 권한 경계 (Authority Boundary)

> **2026-05-11 교차 리뷰 #1 반영.**

세 spec 문서와 per-NPC YAML이 *같은 NPC에 대한 사실*을 적을 때 어디가 권한인지 명시:

| 출처 | 권한 | 소비자 |
|---|---|---|
| `docs/mechanic-spec.md` | **시스템 / 메커니즘 / 인프라 / 일정**의 source of truth | 디자이너 + 향후 코드 작업자 |
| `docs/world-spec.md` | **서사 ecology / design rationale / 트레이드오프 / 디자인 컨텍스트**의 source of truth | 디자이너 (사람을 위한 prose) |
| `docs/mapping-spec.md` | **mechanic ↔ world 정렬**의 source of truth | 디자이너 (drift 점검) |
| `npcs/<name>.yaml` | **NPC operational data**의 source of truth — LLM 시스템 프롬프트에 들어갈 *모든* 내용 | 시스템 프롬프트 빌더 (Phase 1.0+) |
| `rules/*.yaml` | **Global game rules**의 source of truth | 시스템 프롬프트 빌더 + 게임 로직 |

**핵심 룰: 같은 사실은 한 곳에만 적는다.** 백스토리의 경우:

- `world-spec.md`의 NPC 섹션 = *디자인 exposition* (왜 이 백스토리인지, 어떤 ecology 안에 들어가는지, 다른 NPC와 어떻게 대조되는지). 산문형, 사람을 위한 글.
- `npcs/<name>.yaml`의 `identity.forgotten_life.backstory_summary` = *LLM이 보는 1-3문장 요약*. 시스템 프롬프트 빌더가 직접 prompt에 박을 텍스트.

world-spec은 *왜*를 설명하고, yaml은 *무엇*을 LLM에게 준다. 둘이 *내용 자체*를 복제하지 않는다.

## Worldview — `docs/world-spec.md` 골격 (디자이너 prose, LLM 직접 입력 X)

### Premise

어딘가의 외딴 섬. 사람들이 "잊고 싶음 / 후회 / 도망 / 포기"의 감정 무게로 떠밀려 흘러오는 곳 — 자발적 도착이 아니다. 도착한 자는 점차 자아를 잃고 자기 행위(직업 / 관계 / 의식)만 반복하는 NPC가 된다. 섬은 *망각을 보존하는 시스템*이고, NPC들의 트로프 행위(망치질, 그물 당김, 손짓, 파도 응시)가 그 시스템의 작동 형태다. 보트는 처음부터 있는 게 아니라 *떠나고 싶다는 의지가 회복된 자에게만 보인다*.

### 플레이어

풍랑을 만나 죽기 직전 반포기 상태에서 흘러옴. 자기도 망각의 대상이었으나, NPC들과 대화하면서 자기 자신의 깨어남도 동시 진행. 게임 마지막에 "이게 현실인지 꿈인지" 모호함이 *thematic layer*로 남는다 (binary reveal X). 보트 모먼트 메타 엔딩 모놀로그가 양쪽 해석 모두 허용.

### 4 NPC의 자리 (design exposition)

이 섹션은 *왜 이 4명인지*에 대한 디자이너 사고를 담는다. 각 NPC의 *operational data* (실제 sample_lines, ending_gates, name_candidates 등)는 `npcs/<name>.yaml`이 권한.

- **수리공** (`npcs/surigong.yaml`) — 망각 성공, *purpose*-loop 갇힘. 망치질이 망각의 의식. "완성"의 약속을 두고 떠난 자.
- **어부** (`npcs/eobu.yaml`) — 망각 성공, *transaction*-loop 갇힘. 거래가 망각의 의식. 거래해온 것의 가치가 비었음을 안 자.
- **할머니** (`npcs/halmoni.yaml`) — 망각 *부분 실패*. 가장 오래 머물러서 루프를 인지. 시간이 사람을 데려가는 것을 본 자.
- **혜안** (`npcs/hyean.yaml`) — 망각 *완전 실패*. 본 것의 무게에 짓눌려 도망 왔으나, 섬조차 그녀의 눈을 못 막음. 사람을 안 보려고 등 돌리고 파도만 본다. *3 + 1 메타* 구조의 1.

### 두 종류의 깨어남 — ecology 정합

기억하는 깨어남 (3명) vs 수긍하는 깨어남 (혜안 1명). 4-corner symmetric matrix가 아닌 *3+1 비대칭*. narrative ecology의 핵심.

### 이름의 무게 — 비대칭

다른 셋은 *호칭만 남은 자*. 혜안은 *이름밖에 안 남은 자*. boat moment에서:
- 3명 = 이름의 *회수* ("나는… 박OO이었어")
- 혜안 = 이름의 *의미 전환* ("내 이름이 혜안인 건 저주였어. 근데 이제는…")

이 비대칭의 framework는 ADR 0016 (Boat Moment Name Beats), 혜안 사례 적용은 ADR 0015.

### v1.1 후보 — 사이비 archetype

5번째 NPC archetype 후보로 *사이비 / 전도하는 자*. 망각의 섬의 *자기-보존 면역체계*. 혜안과 거울 관계 — 진짜 자아 못 놓은 자 (혜안) vs 가짜 자아 덮어쓴 자 (사이비). v1.1 deferral은 ADR 0017.

## NPC Spec Changes (vs 기존 PRD)

### 수리공 / 어부 / 할머니 — yaml 신설

- **메커니즘 변경: 없음.**
- **`identity.forgotten_life` 필드 신설:**
  - `profession` (1줄, 어떤 직업/역할이었나)
  - `core_wound` (memory_tags vocab 중 *단일* primary tag)
  - `backstory_summary` (1-3문장, LLM 시스템 프롬프트에 직접 박힘)
  - `name_candidates` (boat moment LLM 입력에 들어갈 한국 이름 후보 풀)
- **`identity.name_status: "forgotten"` + `identity.current_display_name: null`** — 다른 NPC는 호칭만 남은 상태. boat moment에 LLM 합성으로 회수.
- **Boat moment 새 beat** — 메타 엔딩 모놀로그에서 *처음으로 자기 이름을 기억해냄*. ADR 0016 framework.

### 혜안 — 5가지 변경

| 항목 | 기존 PRD | 신규 |
|---|---|---|
| Lore positioning | space-loop awareness ("audio is the clue") | 못 잊은 자. 이름이 능력이자 저주. 사람을 안 보려 등 돌림 |
| 깨어남 종류 | 발견 progression | *체념 + 발견 progression* — 다른 NPC가 *기억하는 깨어남*이라면, 혜안은 *수긍하는 깨어남* |
| memory_tag affinity | pattern, fear, loss, home | (유지) — lore 변경에도 태그 합치 |
| 4-band 0-30 / 30-60 / 60-85 | (대사 유지) | (대사 유지, 톤 라벨만 명시) |
| 4-band 85+ | "파도가 진짜라면 이렇게 반복될 리 없어. 우리... 어디에 있는 거야?" | **"이미 알고 있었어. 처음부터. 그저… 더 보고 싶지 않았던 거야."** |
| Boat moment | (다른 셋과 동일하게 이름 회수) | 이름의 *의미 전환* ("내 이름이 혜안인 건 저주였어. 근데 이제는…") |

혜안의 `identity.name_status: "given"` + `identity.current_display_name: "혜안"`. ADR 0015 + 0016 (framework instance).

기존 PRD의 "혜안의 Audio-Independent Awakening" 섹션 (대사 자체가 자기충족 → 오디오 무관)은 *그대로 유효*. 오디오는 atmosphere QoL.

### 사이비 — v1.1 deferral

ADR 0017 참조. 4-NPC 슬롯 보호 + 혜안과 거울 관계 ecology 보존이 목적.

## Mechanic ↔ Lore Mapping — `docs/mapping-spec.md` 골격

| Mechanic (PRD) | Lore (망각의 섬) |
|---|---|
| Shipwreck frame | 반포기 상태로 떠밀려옴 (자발 X) |
| NPC가 트로프에 갇힘 | 망각의 의식(ritual)이 자아의 빈자리를 채움 |

| 루비 무한 루프 (수리공) | 결핍감으로 망각을 유지하는 자가-기제 |
| 카운터 글리치 사라짐 (boat moment) | 결정 순간에 환각이 무너짐 |
| 글로벌 awareness ≥40 mutter | 망각 시스템이 *흔들리기 시작*하는 신호 |
| 할머니의 시각적 hint | 가장 오래 머문 자가 *루프의 가장자리*를 본다 |
| 혜안의 4-band escalation | 사람을 안 보려 했던 자가 *처음으로 동행을 발견*하는 과정 |
| Boat moment 이름 beat | 망각된 자의 이름 회수 / 못 잊은 자의 의미 전환 (ADR 0015, 0016) |

이 매핑은 *살아있다*. 새 메커니즘 추가 / lore 보강 시 매핑 표 갱신이 PR 룰. 메커니즘이 lore와 어긋나면 둘 중 하나가 바뀌어야 함 — *암묵적 표류 금지*.

## Phase 0 Done Criteria

> **2026-05-11 교차 리뷰 #5 반영.** 완료 정의 없으면 spec drift 시작.

Phase 0가 완료됐다 판정하는 4개 조건. 4개 모두 충족해야 Phase 1.0 진입.

### 1. NPC yaml 4종이 *minimum operational*

- `voice.awakening_bands` 4밴드 각 1-2 sample_lines 채워짐 (혜안은 PRD + ADR 0015 기준 정확히 작성)
- `memory_tag_affinity` 4명 모두 명시
- `ending_gates` 4명 모두 4 type (liberation / despair / denial / rest) 명시
- `identity.forgotten_life.backstory_summary` 1-3문장 채워짐
- `identity.name_status` + `current_display_name` 명시 (forgotten/given/null)
- `diegetic_fallback` 라인 채워짐

추가 sample_lines 5-10개 per band 작성은 Phase 2-3 authoring (PRD 권한).

### 2. 3-spec cross-link 작동

- `mechanic-spec.md` ↔ `world-spec.md` ↔ `mapping-spec.md` 사이의 참조가 깨지지 않음
- mapping-spec의 모든 행이 mechanic 사실 + lore 사실 *둘 다*를 가리킴
- world-spec의 NPC 섹션이 yaml 파일을 *명시적으로 가리킴* (예: "operational data는 `npcs/hyean.yaml` 권한")

### 3. ADR 20개 모두 작성, `Status: Accepted`

- 0001-0013 (historical) + 0014-0020 (today) = 20개
- 각 ADR이 `Context / Decision / Alternatives Considered / Consequences / Related` 섹션 포함
- ADR 0020 (cross-review followup)이 이 갱신의 audit trail 보존

### 4. ★ 손-합성 검증 — Phase 0의 진짜 테스트

**`npcs/hyean.yaml` + `rules/*.yaml` + `docs/mapping-spec.md` 만 보고**, 다음을 *손으로 빈 종이에* 합성할 수 있어야 함:

- 혜안에 대한 시스템 프롬프트 (PRD "## Awakening Guideline Schema (per NPC)" 형식)
- awareness 70 시점에 LLM에 전달될 *전체 컨텍스트* (memory_tags hint, awakening_guidelines, tone palette band 60-85, conversation history placeholder)

손으로 못 적으면 → schema가 *부족함*. 부족한 필드 식별 후 yaml schema 보강. Phase 1.0 빌더 짜기 *전에* 발견하는 게 핵심.

이 테스트는 *시스템 프롬프트 빌더를 짜는 행위*의 사전 시뮬레이션. 빌더 짜다가 schema 갈아엎는 사이클을 차단한다.
