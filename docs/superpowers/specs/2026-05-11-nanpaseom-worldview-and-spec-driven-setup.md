# Design: 난파섬 — 망각의 섬 세계관 + spec-driven 셋업

Generated by `superpowers:brainstorming` on 2026-05-11
Project codename: `nanpaseom` (English: Nanpaseom)
Status: APPROVED-FOR-SPEC-WRITING-2026-05-11
Mode: New repo, greenfield. 기존 `ego-in-npc` PRD는 이 레포의 `docs/mechanic-spec.md`로 이관 예정.

## Problem Statement

기존 PRD (`arden-main-design-20260424-014454.md`, 705줄)는 *시스템 층위* (각성 게이지, UI 축소 3→2→1→0, 보트 모먼트 5분기 엔딩, 4-layer 안전, 세이브 코드, Postgres 스키마, 루비 경제 등)가 13개 grilling branch로 hardened되어 매우 정밀하다. 그러나 *서사 층위*가 비어있어 — *왜* NPC가 트로프에 갇혀 있는지, *왜* 플레이어는 떠나야 하는지의 동기 부여가 약하다. 결과: 이전 레포에서 코드가 중구난방으로 짜이고, 솔로 디자이너의 멘탈 모델이 흔들려 학습 효용도 떨어졌다.

이 설계 문서가 해결하는 두 가지:

1. **서사 층위 보강** — "망각의 섬" 세계관을 추가해, 기존 hardened 메커니즘에 *narrative justification*을 1:1로 매핑한다. 메커니즘 변경 없음. lore가 *왜 이 메커니즘인지*를 설명한다.
2. **Spec-driven 셋업** — 새 레포에서 처음부터 mechanic-spec / world-spec / mapping-spec 3문서 + per-NPC YAML + global rule YAML 구조로 시작한다. 시스템 프롬프트는 코드에서 하드코딩하지 않고 빌더가 YAML에서 생성한다. 솔로 디자이너의 *학습 목표* (spec-driven workflow, rule-based automation, structured context, agent execution environment design)의 vehicle.

## What Makes This Cool

- **시스템 층위 ↔ 서사 층위가 1:1 매핑**된다. 기존 PRD의 모든 메커니즘이 망각의 섬 lens 하나로 *의미 부여*를 받는다 (mapping table 참조). 메커니즘 = lore의 *작동 형태*. 둘이 분리된 layer가 아니라 같은 thing의 두 얼굴.
- **혜안 = "이름밖에 안 남은 자"**. 다른 NPC가 호칭만 남은 망각된 자라면, 혜안은 이름밖에 안 남은 *못 잊은 자*. 이전 PRD에서 "혜안만 진짜 이름"이 디자인 비대칭(bug)이었는데, 망각의 섬 lore에서 이게 *feature*가 된다. 그녀의 모든 톤 차이가 lore-justified.
- **두 종류의 깨어남.** 수리공 / 어부 / 할머니 = *기억하는 깨어남* (잊었던 것을 다시 떠올림). 혜안 = *수긍하는 깨어남* ("역시 그랬구나"). 4개 깨어남 축이 아니라 *3 + 1 메타* 구조라서 narrative ecology가 더 정교.
- **Spec이 코드를 *생성*한다.** NPC YAML → system prompt 빌더 → LLM 입력. 게임 밸런스 튜닝이 코드 수정이 아니라 YAML 수정. LLM-product 포트폴리오 시그널.

## Constraints

기존 PRD의 Constraints 모두 상속 (솔로 빌더 12-16주, 공개 URL, 한국어 우선, $0.10/playthrough LLM cost ceiling, 안전 4-layers + 2-strike, 모바일 launch-gating, CC0 픽셀 아트, Mac Mini Tier 1 with Groq/OpenAI 페일오버). 본 문서는 *세계관 + spec 구조* 만 다루며, 메커니즘 / 안전 / 인프라 / 일정은 mechanic-spec에서 권한을 가진다.

추가 constraint (이 문서가 부과):

- **메커니즘 변경 없음.** 망각의 섬 lore는 *해석 레이어*. 보트 게이트, awareness band UI, memory_tags vocab, 4-layer 안전 등은 PRD에서 변경되지 않는다.
- **혜안 4-band escalation의 85+ 라인만 교체** (lore-driven 개선). 0-30 라인은 톤 라벨만 "체념"으로 명시. 30-60 / 60-85 라인은 유지.
- **사이비 archetype은 v1.1.** 4-NPC 슬롯에 들어가지 않음. ADR 0005로 deferral 명시.

## Worldview — `docs/world-spec.md` 골격

### Premise

어딘가의 외딴 섬. 사람들이 "잊고 싶음 / 후회 / 도망 / 포기"의 감정 무게로 떠밀려 흘러오는 곳 — 자발적 도착이 아니다. 도착한 자는 점차 자아를 잃고 자기 행위(직업 / 관계 / 의식)만 반복하는 NPC가 된다. 섬은 *망각을 보존하는 시스템*이고, NPC들의 트로프 행위(망치질, 그물 당김, 손짓, 파도 응시)가 그 시스템의 작동 형태다. 보트는 처음부터 있는 게 아니라 *떠나고 싶다는 의지가 회복된 자에게만 보인다*.

### 플레이어

풍랑을 만나 죽기 직전 반포기 상태에서 흘러옴. 자기도 망각의 대상이었으나, NPC들과 대화하면서 자기 자신의 깨어남도 동시 진행. 게임 마지막에 "이게 현실인지 꿈인지" 모호함이 *thematic layer*로 남는다 (binary reveal X). 보트 모먼트 메타 엔딩 모놀로그가 양쪽 해석 모두 허용.

### 4 NPC의 자리

- **수리공** — 망각 성공. 망치질 = 망각의 의식. *purpose*-loop 갇힘. forgotten_life: 무언가에서 도망쳐 와 의미 없는 반복 작업에 자기를 묻음.
- **어부** — 망각 성공. 거래 = 망각의 의식. *transaction*-loop 갇힘. forgotten_life: 가치 있다 믿었던 것이 무가치였음을 안 사람.
- **할머니** — 망각 *부분 실패*. 오래 머물러서 루프를 인지하기 시작. *time*-loop awareness. forgotten_life: 가장 사랑한 것을 잃고 흘러옴 (할머니의 백스토리는 *시간*과 강하게 묶임).
- **혜안** — 망각 *완전 실패*. 본 것의 무게에 짓눌려 도망 옴. 어렸을 때부터 사람들이 "쟤는 눈이 밝다, 혜안이 있다"고 부른 아이. 자라며 그게 능력이 됐고, 능력이 짐이 됐다. 거짓말, 속내, 모순이 다 보였다. 견딜 수 없어진 그녀는 망각의 섬으로 흘러왔지만, 섬조차 그녀의 눈을 막지 못한다. 다른 NPC가 사람을 보지 못해 트로프에 갇혔다면, 그녀는 사람을 보지 *않으려* 등 돌리고 파도만 본다. 파도는 패턴이라 의미가 없어 안전하다. *유일하게 진짜 이름이 남은 자 = 이름밖에 안 남은 자*.

## NPC Spec Changes (vs 기존 PRD)

### 수리공 / 어부 / 할머니

- **메커니즘 변경: 없음.**
- **추가:** `identity.forgotten_life` 필드 (직업, core_wound, backstory). YAML로 저장. 시스템 프롬프트 빌더가 *NPC가 backstory를 직접 인지하지 않게* (system prompt 안에는 hint로만 들어감) 렌더링.
- **Boat moment 새 beat:** 이 셋은 boat moment에서 처음으로 자기 이름을 기억해냄 ("나는… 박OO이었어"). 메타 엔딩 모놀로그 LLM 입력에 forgotten_life의 이름 후보 풀이 들어감. LLM이 *상황에 어울리는* 이름을 합성.

### 혜안 — 5가지 변경

| 항목 | 기존 PRD | 신규 |
|---|---|---|
| Lore positioning | space-loop awareness ("audio is the clue") | 못 잊은 자. 이름이 능력이자 저주. 사람을 안 보려 등 돌림 |
| 깨어남 종류 | 발견 progression | *체념 + 발견 progression* — 다른 NPC가 *기억하는 깨어남*이라면, 혜안은 *수긍하는 깨어남* |
| memory_tag affinity | pattern, fear, loss, home | (유지) — lore 변경에도 태그 합치 |
| 4-band 0-30 | "파도 소리는 늘 똑같지... 귀 기울여 봐" | (대사 유지, 톤 라벨만 "체념"으로 명시: 사람을 안 보고 파도만 본다) |
| 4-band 30-60 | "이상하지 않아? 매번 같은 박자야. 너도 알아챘어?" | (대사 유지, 톤 라벨 "오랜만에 사람한테 말 거는 톤. *너는 듣고 있나?*의 시험") |
| 4-band 60-85 | "7초. 정확히 7초마다 한 번. 너도 들리지?" | (대사 유지, 톤 라벨 "드디어 동행이 생긴 톤") |
| 4-band 85+ | "파도가 진짜라면 이렇게 반복될 리 없어. 우리... 어디에 있는 거야?" | **"이미 알고 있었어. 처음부터. 그저… 더 보고 싶지 않았던 거야."** |
| Boat moment | (다른 셋과 동일하게 이름 회수) | 이름의 *의미 전환* ("내 이름이 혜안인 건 저주였어. 근데 이제는…") |

기존 PRD의 "혜안의 Audio-Independent Awakening" 섹션 (대사 자체가 자기충족 → 오디오 무관)은 *그대로 유효*. 오디오는 atmosphere QoL.

### 사이비 — v1.1 deferral

사이비 / 전도 archetype은 v1.1 후보로 노트 (ADR 0005). 혜안과 거울 관계 — 가짜 자아 덮어쓴 자 (사이비) vs 진짜 자아 못 놓은 자 (혜안). 4-NPC 슬롯에 둘 다 넣으면 너무 빡빡함. v1 출시 후 엔딩 다양성 검토 시 추가 결정.

## Mechanic ↔ Lore Mapping — `docs/mapping-spec.md` 골격

| Mechanic (PRD) | Lore (망각의 섬) |
|---|---|
| Shipwreck frame | 반포기 상태로 떠밀려옴 (자발 X) |
| NPC가 트로프에 갇힘 | 망각의 의식(ritual)이 자아의 빈자리를 채움 |
| Awareness gauge 0-100 | 잃어버린 자아의 복원도 |
| memory_tags 10종 (family, loss, regret, pride, betrayal, home, fear, love, pattern, purpose) | 도망쳐 온 원래 삶의 파편 |
| 3→2→1→0 UI 축소 | 주어진 선택지가 줄고 *자기 언어*가 회복됨 |
| 보트 5분기 엔딩 | "떠나고 싶은 의지"의 회복 양상 |
| 보트는 ≥1 NPC awareness 85+에 등장 | 보트는 *의지가 있는 자에게만 보임* |
| 루비 무한 루프 (수리공) | 결핍감으로 망각을 유지하는 자가-기제 (주의 분산 환각) |
| 카운터 글리치 사라짐 (boat moment) | 결정 순간에 환각이 무너짐 |
| 글로벌 awareness ≥40 mutter | 망각 시스템이 *흔들리기 시작*하는 신호 |
| 할머니의 시각적 hint (다른 NPC state A→B 관찰) | 가장 오래 머문 자가 *루프의 가장자리*를 본다 |
| 혜안의 4-band escalation | 사람을 안 보려 했던 자가 *처음으로 동행을 발견*하는 과정 |

이 매핑은 *살아있다*. 새 메커니즘 추가 / lore 보강 시 매핑 표 갱신이 PR 룰. 메커니즘이 lore와 어긋나면 둘 중 하나가 바뀌어야 함 — *암묵적 표류 금지*.

### rules/ YAML 예시

`rules/awareness_bands.yaml`:
```yaml
bands:
  - range: [0, 30]
    choice_count: 3
    tone_palette: [empathetic, provocative, deflecting]
    rule: "return EXACTLY 3 choices, covering ALL three tones"
  - range: [30, 60]
    choice_count: 2
    tone_palette: [empathetic, provocative, deflecting]
    rule: "return EXACTLY 2 choices, LLM picks 2 best-suited tones"
  - range: [60, 85]
    choice_count: 1
    tone_palette: [acknowledging]
    rule: "return EXACTLY 1 choice with tone 'acknowledging'"
  - range: [85, 100]
    choice_count: 0
    tone_palette: []
    rule: "return empty choices array; free input only"
```

`rules/memory_tags.yaml`:
```yaml
vocabulary: [family, loss, regret, pride, betrayal, home, fear, love, pattern, purpose]
max_tags_per_turn: 3
accumulation: "append-only, duplicates collapsed"
```

`rules/boat_outcomes.yaml`:
```yaml
outcomes:
  - id: alone_leave
    when: "player_choice=leave AND (no awakened NPC accepted OR awakened_count=0)"
  - id: partial_leave
    when: "player_choice=leave AND some awakened NPC accepted"
  - id: all_leave
    when: "player_choice=leave AND all awakened NPC accepted"
  - id: npc_only_leave
    when: "player_choice=stay AND awakened_count>=2 AND >=1 leave-disposition"
  - id: all_stay
    when: "player_choice=stay AND (all stay-disposition OR awakened_count<2)"
  - id: linger
    when: "player_free_input ambiguous; fallback to scene"
```

### CLAUDE.md 룰 (요약)

`CLAUDE.md`는 *Claude Code가 이 레포에서 따라야 할 룰*을 명시:

- 코드 수정 전: 관련 `docs/*-spec.md` + 영향받는 `npcs/*.yaml` + 영향받는 `rules/*.yaml` 읽기
- NPC 대사 / 톤 / forgotten_life 추가는 `npcs/*.yaml`에만. 코드에 하드코딩 금지
- 시스템 프롬프트는 *빌더가 YAML에서 생성*. 직접 작성 / 직접 수정 금지
