# ADR 0034: 쿠키 보안 속성 4종 + bearer UUID 의식적 수용

- Status: Accepted
- Date: 2026-08-20
- Deciders: Arden, Claude (공개 배포 준비 talpi 런 — 패널 `[BLOCKING]` 지적을 사람이 검토 후 수용 결정)

## Context

ADR 0033으로 신원이 쿠키 하나에 수렴하면서, 그 쿠키의 속성 세트가 곧
방어선 전부가 됐다. 기존 쿠키는 속성이 느슨했고(영속성은 ADR 0037에서
이미 결정), 리뷰 패널은 "쿠키 값이 서명 없는 bearer — 값을 아는 자가
곧 주인"을 `[BLOCKING]` 으로 지적했다. 서명/회전 토큰 도입 여부를
사람이 판단해야 했다.

## Decision

1. **속성 4종 고정**: `HttpOnly; Secure; SameSite=Lax;
   Max-Age=15552000(180일)` + `Path=/`. 발급은 단일 경로
   (`app/api/session_cookie.py` — 세션 상수 단일 홈 컨벤션).
   - HttpOnly: JS에서 자격증명 접근 차단 (XSS 시 탈취 방지 1겹).
   - Secure: 평문 HTTP 전송 차단.
   - SameSite=Lax: cross-site POST에 쿠키 미전송 (CSRF 기본 방어).
     이 선택은 "프론트와 API가 same-origin" 배포 형태를 함의 — 별도
     CDN 도메인에서 API를 부르는 구조는 이 결정과 함께 재검토.
   - Max-Age 180일: 영속성 근거는 ADR 0037.
2. **로컬 개발 예외는 하나**: env 플래그 `NANPASEOM_INSECURE_COOKIE`
   가 켜진 경우에만 Secure 생략 (http 로컬 개발용). 기본값(플래그
   없음)은 항상 Secure — 배포 환경에서 플래그를 켜지 않는 한 무조건
   성립.
3. **쿠키 값 = 서명 없는 bearer UUID, 의식적 수용**: 값을 아는 자가 곧
   주인. 방어는 3겹 — UUID 엔트로피(추측 불가) + HttpOnly(JS 탈취
   차단) + Secure(전송 노출 차단) — 가 전부다. 서명/회전 토큰은
   도입하지 않는다. 익명 개인 프로젝트(지인 링크 배포) 규모에서 키
   관리 인프라가 과잉이라는 판단. **커뮤니티 공개 전 재검토.**

## 커뮤니티 공개 전 재검토 목록

지인 링크 규모에서 의식적으로 수용하고, 커뮤 공개 전 일괄 재검토하는
항목들 (이 목록이 단일 서식지):

- 쿠키 bearer (위 3항 — 서명/회전 없음)
- 세이브 코드 무차별 대입은 조건부 완화 (redeem 시도 제한 — 단일 프로세스
  + 직결 IP 전제 안에서만 성립, ADR 0039). 유출 대응은 회전 경로가 생겨
  절반만 해소 (ADR 0038) — 코드를 먼저 redeem 한 침입자는 이미 쿠키
  바인딩을 얻었고 회전은 코드만 죽이므로, *이미 들어온 자를 축출할* 경로는
  여전히 없다 (축출의 전제 = 계정)
- 익명 세션 대량 민팅 — bootstrap 은 무인증 + LLM 오프닝 비용. 파생:
  (1) 0턴 코드 발급과 결합 시 유효 세이브 코드 모집단 부풀리기 가능,
  (2) 밴이 세션 단위라 쿠키 삭제 + 재bootstrap으로 밴 우회 가능
  (2-strike는 새 세션에서 다시 작동)
- 대화 기록 무기한 보존, 플레이어 측 삭제 경로 없음
- 조용한 덮어쓰기 — 서버가 세션을 모르면 bootstrap 이 묻지 않고 새
  번호로 쿠키를 덮는다 (대화 중 401 → 자동 재bootstrap 포함). 발생
  조건이 서버 DB 유실/복구뿐이라 극히 드물고, 그 경우 진짜 복구
  열쇠는 세이브 코드 ("쿠키는 편의, 코드가 열쇠"). 묻고-리셋 UI는
  도입하지 않음.

## Alternatives Considered

- A. ★ chosen — bearer UUID + 속성 4종 + 재검토 딱지.
- B. 서명 토큰 (HMAC 등) — 기각. DB 조회로 세션 존재를 어차피
  확인하므로 서명이 막는 건 "DB에 없는 값 위조"뿐인데, 그건 서버 전용
  민팅(ADR 0033)이 이미 막는다. 유출 대응(회전)은 서명만으론 안 되고
  만료/재발급 체계가 필요 — 규모 대비 과잉.
- C. SameSite=Strict — 기각. 외부 링크로 진입하는 첫 내비게이션에
  쿠키가 안 실려 "돌아오면 내 섬 그대로" 경험을 해침. Lax가 CSRF
  방어와 복귀 경험의 균형점.

## Consequences

- 테스트: http TestClient에서 Secure 쿠키 재전송 문제는
  `NANPASEOM_INSECURE_COOKIE` 로 해소 (게이트 그린 유지).
- 커뮤 공개가 실제로 다가오면 이 ADR의 재검토 목록이 그대로 하드닝
  백로그가 된다.
