# ADR 0037: 세션 쿠키 Max-Age 180일 영속 (백필)

- Status: Accepted
- Date: 2026-08-19 (결정 시점 — 기록은 2026-08-20 백필)
- Deciders: Arden, Claude (직전 talpi 런 smoke fix)

## Context

직전 런의 스모크 시나리오("탭 닫고 다음날 다시 열면 그대로 이어짐")를
검증하던 중, 쿠키가 Max-Age 없는 **세션 쿠키**로 발급되고 있음이
드러났다 — 브라우저 완전 종료 시 소멸하여, 며칠 뒤 돌아온 플레이어의
진행이 유실된다. 이 게임의 핵심 경험은 "같은 브라우저로 돌아오면
하루든 한 달이든 내 섬이 그대로"이고, 신원이 쿠키 하나뿐이라 쿠키
소멸 = 진행 유실(세이브 코드를 안 받아뒀다면)이다. smoke fix 로
락인됐으나 ADR 미기록이어서 백필한다.

## Decision

- 세션 쿠키 대신 **`Max-Age=15552000` (180일) 영속 쿠키**로 발급한다.
  발급 시점마다 갱신되므로(bootstrap/redeem 응답의 Set-Cookie) 활동
  중인 플레이어의 만료는 계속 밀려난다.
- **180일인 이유**: 캐주얼 플레이어의 복귀 간격(몇 주~몇 달)을 여유
  있게 커버하면서, 무기한이 아니라는 상한을 둔다 — 방치된 브라우저에
  자격증명(bearer UUID, ADR 0034)이 영원히 남지 않도록. 이 값은
  `app/api/session_cookie.py` 의 `SESSION_COOKIE_MAX_AGE` 단일 상수
  (B6 계약 리터럴).

## Alternatives Considered

- A. ★ chosen — 180일 영속.
- B. 세션 쿠키 유지 — 기각. 핵심 경험과 정면 상충 (브라우저 종료 =
  섬 유실). 발견 즉시 스모크 fail 처리됐다.
- C. 만료 없는 초장기(예: 10년) — 기각. 방치 기기에 bearer 자격증명이
  사실상 영구 잔존. 180일이면 "돌아오면 그대로"엔 충분.

## Consequences

- 만료로 쿠키가 사라진 초장기 복귀자는 신규 세션으로 시작 — 복구
  열쇠는 세이브 코드 (「쿠키는 편의, 코드가 열쇠」, ADR 0033/0034).
- 속성 세트 전체(HttpOnly/Secure/SameSite=Lax 포함)의 권한 서식지는
  ADR 0034 — 이 ADR은 영속성(Max-Age) 결정의 근거만 담는다.
