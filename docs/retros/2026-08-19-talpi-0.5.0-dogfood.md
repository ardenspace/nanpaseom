# talpi 0.5.0 도그푸드 런 소감 — 2026-08-19

난파섬 Phase 1.0 Sub-3 (프론트엔드 + 이어하기) 런을 talpi 0.5.0 전체
파이프라인(talpispec → talpiplan → talpirun)으로 완주한 뒤의 회고.
작성: 오케스트레이터 에이전트(Claude). 대화 상대: Arden.

## 런 팩트

- 범위: React+Vite+bun 프론트엔드, 세션 bootstrap(쿠키 identity),
  수리공 오프닝 자동 생성, 재방문 복원, 세이브 코드 발급/redeem.
- 결과: 201 → 239 passed. 커밋 15개 (819dca3..ba1ca0e). 3 페이즈.
- 스펙 패널: 풀 3-리뷰어 × 3라운드, BLOCKING 10건 (5 스펙 fix / 2 인간
  결정 / 3 정합성 fix + 최종 1건 인간 승인 fix).
- 빌드 중 이벤트: 에스컬레이션 1회(세이브 코드 형식 — halt → 인간
  재판정 b "단어 프리픽스" → 재구현), 완주 스모크에서 실버그 1건(세션
  쿠키가 브라우저 종료 시 소멸 → Max-Age 180일), run review FIX 1건
  (확인 다이얼로그 localStorage 힌트 의존 → 무조건 표시).
- 산출 상태: `.talpi/` (spec/plan/conventions/journal/state/handoff/
  manual-check/knowledge). knowledge.md는 check/replay 게이트 클린.

## 에이전트 관점 — 잘 작동한 것

1. **계약 먼저 failing 테스트로 pin.** "redeem은 성공 응답에만 쿠키
   rebind" 같은 미묘한 규칙이 구현 전에 테스트로 박히니, 구현자가
   bootstrap 패턴("503에도 쿠키 세팅")을 복붙하다 틀리는 걸 원천
   차단했다. pin 스텝이 다음 스텝에게 남긴 "이 패턴 여기선 금지" 노트도
   그대로 작동.
2. **fresh-context 검증자의 격리 가치.** /assets 테스트 공백, 확인
   다이얼로그의 localStorage 힌트 구멍, 세이브 코드 형식의 원장 이탈 —
   전부 오케스트레이터와 컨텍스트를 공유하지 않는 눈이 잡았다. 같은
   컨텍스트면 같은 맹점이라는 talpi 전제가 실증됨.
3. **스모크 런 = 진짜 제품 걷기 강제.** 239개 테스트가 그린인데도
   쿠키 유실 버그는 실제 브라우저 완전 종료 시나리오를 걸어야만 나왔다.
   이번 런 최고 가치 캐치.
4. **에스컬레이션의 기계적 규칙이 판단을 이겼다.** 세이브 코드 형식
   halt는 순간 과해 보였지만, 인간이 b(단어 프리픽스, "귀엽다")를 골라
   제품이 실제로 바뀌었다. "작으니까 에이전트가 정하자"보다 "Decided
   건드리면 무조건 인간"이 옳았다는 증거.
5. **패널 수렴 장치(scoped 재실행 + 캡 2 + 기결 원장).** 1라운드
   무제한 → 이후 "새 변경이 만든 문제만 BLOCKING" 스코핑이 없었으면
   fresh 리뷰어들이 매 라운드 새 발견을 민팅해 수렴하지 않았을 것.

## 에이전트 관점 — 마찰/아쉬움

1. **디스패치 인라인 반복 오버헤드.** 매 서브에이전트마다 컨벤션 발췌 +
   계약 + 머신 사실(포트 회피, llama-server 죽이지 마라)을 프롬프트에
   다시 쓰는 게 김. 런 시작 시 "디스패치 공통 서문" 파일을 만들어 참조
   인라인하는 개선 여지.
2. **소규모 수정의 fresh 에이전트 비용.** CSS 토큰 하나(300ms) 고치는
   데도 풀 부트스트랩. 단, 이 규칙이 오케스트레이터의 인라인 몰래 수정
   을 막는 장치라 트레이드오프는 의도된 것 — 비용은 실재함을 기록.
3. **스펙 수정이 만든 2차 모순.** 패널 2라운드 BLOCKING 4건이 전부 내
   1라운드 스펙 수정이 도입한 정합성 문제였다. 재패널 전 자기-정합성
   패스(수정된 조항 간 교차 검토) 한 번이면 라운드 하나를 아꼈을 것.
4. **저널/커밋 순서 스머지.** 저널 append가 커밋 직후에 이뤄져 상태
   파일이 다음 커밋에 실리는 경우가 두어 번 — "커밋이 스텝의 ground
   truth"는 유지되지만 깔끔하진 않았다.
